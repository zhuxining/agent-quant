# 模块职责边界

## 核心原则

各模块的职责必须清晰明确，避免功能交叉和职责模糊。

## 模块分类

### 1. 实时交易系统
- **定位**：实时市场数据分析和决策生成
- **用途**：为用户提供**实盘交易建议**
- **特征**：每次决策都调用 LLM，响应时间较长（30-60s）
- **数据**：实时行情、即时新闻
- **输出**：即时交易建议，无历史回测

**职责**：
- 获取实时市场数据（AkShare/Longport）
- Multi-Agent Team 分析（新闻、技术、基本面、风控）
- 生成交易决策（买入/卖出/持有）
- 提示用户决策依据
- **不负责**：执行交易、记录历史

---

### 2. Paper Trading 系统
- **定位**：策略验证和模拟交易执行
- **用途**：在上线前验证策略有效性，模拟真实交易环境
- **特征**：使用历史数据，一次性回测整个周期
- **数据**：历史价格、历史指标
- **输出**：净值曲线、绩效指标、交易记录
- **执行方式**：批量处理历史数据，无需实时 LLM 调用

**职责**：
- 加载历史数据（从数据库或文件）
- 计算技术指标（向量化/向量化）
- 生成交易信号（基于规则，不使用 LLM）
- 批量回测（快、准确）
- 计算绩效指标（收益率、夏普比率、最大回撤）
- 生成报告（HTML/JSON）
- **不负责**：实时交易、用户交互

---

### 3. 历史数据加载系统（可选）
- **定位**：提供 Paper Trading 和实时交易系统所需的历史数据
- **用途**：支持策略验证和历史回测
- **特征**：批量加载、标准化、事件管理
- **数据类型**：历史行情、历史新闻、历史财务、历史事件
- **存储**：数据库/文件

**职责**：
- 从数据源加载数据（API/CSV）
- 标准化数据格式（OHLCV、事件结构）
- 管理历史事件（手动录入/爬取）
- 提供数据给其他系统

---

## 模块间边界

### 禁止的操作

| 模块 | 禁止 | 原因 |
|------|------|--------|
| 实时交易 | 不要调用回测引擎 | 回测是历史分析，不是实时功能 |
| Paper Trading | 不要执行实时交易 | 回测是批量处理，不是实时交互 |
| Paper Trading | 不要存储用户账户信息 | 回测是模拟环境，不涉及真实用户 |

### 数据流向

```
实时交易:
  [AkShare/Longport] → [实时行情/新闻] → [Multi-Agent Team] → [用户界面]

Paper Trading:
  [历史数据加载器] → [历史行情/技术指标] → [信号生成] → [批量回测] → [报告生成] → [数据库]
```

## 数据隔离

| 系统 | 数据源 | 存储位置 |
|------|--------|----------|
| 实时交易 | AkShare/Longport API | 实时数据表 |
| Paper Trading | 历史数据文件/数据库 | 历史数据表 |
| 历史数据加载器 | 数据库/文件 | 历史数据表 |

## 交互接口

| 功能 | 负责模块 | 说明 |
|------|--------|----------|
| 实时决策 | 实时交易系统 | Multi-Agent 输出交易建议 |
| 历史分析 | Paper Trading 系统 | 提供回测报告 |
| 手动验证 | 研发者 | 在两个系统间切换测试 |

---

## 避免混淆的命名规范

| 模块 | 推荐命名 | 避免 |
|------|----------|--------|
| 实时交易 | `app/agent/` `app/api/` `app/virtual_trade/` | 虚拟（含糊）|
| Paper Trading | `app/backtest/` | 回测（明确） | `app/paper_trading/` |
| 历史数据 | `app/data_feed/`（如新增）| `app/historical/` | `app/backtest/historical/` |
